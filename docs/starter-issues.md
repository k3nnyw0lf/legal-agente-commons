# Starter issues

Ideas for first tasks. When the project has its public GitHub page, each one becomes an issue with these labels. Use made-up data only (see [CONTRIBUTING.md](../CONTRIBUTING.md)).

Labels: `good first issue` (small, clear, a good way in) · `help wanted` (bigger, we need someone to own it).

## Phone intake form (English and Spanish)
Labels: `help wanted`, `design`

A phone-first form for [bringing a case](roadmap.md#2-bringing-a-case): one question per screen, big buttons, English and Spanish. It asks only the basics, plus "Is there a court date or a deadline soon?" A mockup first, then a page that works with the sample case.

## Voice-note capture
Labels: `help wanted`

"Hold to talk" in the phone app: record, send to the existing speech-to-text route (`/api/transcribe`), and save the text as a note on the case. Notes follow the [helper notes rules](access-model.md#helper-notes).

## Helper task feed mockup
Labels: `good first issue`, `design`

A mockup of the [phone helper app](roadmap.md#8-phone-helper-app) feed: task cards with a nameless preview, how long the task takes, and Accept / Not now / Not this type. A picture or a clickable prototype is enough.

## Accessibility audit
Labels: `good first issue`, `accessibility`

Check the public pages and the sample case against WCAG 2.2 AA: keyboard only, a screen reader, 200% text, the dyslexia fonts, color contrast in light and dark. Write down what fails and where.

## Spanish guide translation
Labels: `good first issue`, `translation`

Translate a plain-language guide into Spanish, in plain words. A second Spanish speaker checks it before it is used.

## Add a language
Labels: `good first issue`, `translation`

Speak Haitian Creole, Portuguese or another language? Help add it. The first step is the [one-file-per-language](roadmap.md#10-languages) screen text; until then, start a word list for the main buttons and headings. AI first drafts are allowed but stay marked "unreviewed" until a speaker checks them.
